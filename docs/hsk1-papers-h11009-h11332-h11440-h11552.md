reading questions. Check it against a printed key when one is found and update `server/data/hsk11552.js`


## Pictures

For now every question picture is **cut out of the booklet** (the user asked for this first, before new
illustrations): singles 960×720, A/B/C strips 1500×640, A–F boards 1200×1600, JPEG, about 750–820 KB per
paper. Positions came from `pdftohtml -xml` (H11009, H11332, H11440) or from hand-placed regions with
automatic trimming (the H11552 scan). The worked-example pictures (`l1-example`, `l2-example`,
`r1-example`) are H11112's illustrations, since the examples are identical.

Next step: replace each cut-out with a new illustration (step 6 of the guide), checking each keeps the
printed answer correct, then publish the paper.

## Audio still to do

This machine has no `ffmpeg`, so the WMA and WAV recordings couldn't be converted. With ffmpeg:

```
ffmpeg -i mock_test_pdf/11332/H11332.wma -codec:a libmp3lame -b:a 64k client/public/hsk1/h11332/listening.mp3
ffmpeg -i mock_test_pdf/11440/H11440.wav -codec:a libmp3lame -b:a 64k client/public/hsk1/h11440/listening.mp3
```

Then measure each decoded length (the guide shows how), set `listeningSeconds` (H11332's 900 is an estimate),
and add the audio hashes to the paper checks in `server/test/hsk1.test.js`.

## Checks

`server/test/hsk1.test.js` checks, for each paper: the key typed separately from the answer sheet,
8 groups × 5 questions with examples, 20 distinct pictures that are real JPEGs, the audio hash and length
where there is audio, full marks with the key, and `publishedByDefault: false`.
