Super admins can send Chinese practice reminders manually from **Practice reminders** in the sidebar or dashboard (`/admin/reminders`). The page uses the existing Google SMTP, SMTP, or Resend email configuration. Configure it from **Email settings** first.

Use **Choose students** to search by name or email, filter by inactivity, and select recipients. **Select all matching** adds the current filtered group to your selection; **Show selected** lets you inspect selections across searches and pages. A row's **Remind** button prepares a reminder for just that student. Edit the subject and message, select **Review reminder**, inspect the recipient count and email preview, then select **Send to … students**. Reviewing does not send mail. Only students with an unexpired subscription to a published Chinese course are eligible. Accounts with several eligible subscriptions receive one email. Deleted users, staff, expired subscriptions, unpublished courses, invalid addresses, and students who have stopped reminders are excluded.

The student list shows the latest recorded practice and last successfully sent reminder. Practice is derived from completed lessons, saved quiz/test attempts, submitted HSK mock tests, saved vocabulary reviews, and uploaded conversation recordings. Sign-ins and unfinished mock exams do not count. Standalone exercises stored only in the browser are outside this report. The 3/7/14-day filters use full elapsed 24-hour periods. Students without saved practice history appear in the separate **No recorded practice** filter, with an unknown inactivity duration. Displayed dates use Nepal time. **Refresh students** reloads eligibility and activity without changing the message; any unavailable selections must be removed before reviewing. Student activity is loaded independently of delivery-progress polling.

The server resolves selected student IDs against current eligible subscriptions; the browser cannot supply arbitrary recipient addresses. Reviews expire after 15 minutes and are tied to the acting super admin, message, selected recipients, and practice-site origin. If any of these change, review again. New subscribers are not added to an existing selection automatically. Double-clicks and retries of the same confirmed request reuse the same persisted send, including when the original HTTP response is lost. The existing API broadcast flow remains supported when no student ID selection is supplied; the interactive page always supplies an explicit selection.

Each student receives an individual plain-text email with a greeting, the message, a link to `/my-courses`, and an unsubscribe link. Set `CLIENT_URL` to the student-facing website URL before sending; local development defaults to `http://localhost:5173`. Unsubscribe links show a confirmation page and do not change preferences until the student selects **Stop practice reminders**. They affect reminder emails only, preserving login codes, password resets, and subscription access.

The send queue lives in MongoDB. The running API processes one recipient at a time, with a two-second pause between attempts. There is no recurring reminder schedule. The worker checks current subscription access, email address, role, and reminder preference immediately before each send. All running instances claim recipients atomically, and successful recipients are not sent again. Keep the API running to process queued reminders.

**Recent reminders** shows the last ten sends and refreshes while work remains. Sent means the email provider accepted the message, not guaranteed inbox delivery. Failed, skipped, and unconfirmed outcomes are reported separately. A process interruption after starting a send may leave its outcome unknown; after ten minutes, stale attempts become unconfirmed and are not automatically resent. Provider failures are not retried automatically. Authentication mail keeps its existing behavior; reminder delivery fails if no provider is configured, including in development.

The request ID index is initialized before accepting requests. A confirmed reminder supports up to 5,000 unique students. Provider sending limits still apply. The default sender, credentials, and account policy are those configured in Email settings; this feature does not change them. Reminder queue actions are recorded in the admin audit log.

Unsubscribe tokens are signed with `JWT_SECRET`, scoped to reminder preferences, and cannot be used as login tokens. Rotating that secret invalidates old unsubscribe links. Plain-text email content and recipient snapshots are stored in the private reminder collection; only super admins can access reminder APIs, apart from the signed unsubscribe endpoint.

Validation: `npm --prefix server test`, `npm --prefix client run build`, `npm --prefix client run lint`, and `npm --prefix client run test:navigation -- e2e/practice-reminders.spec.js`.
